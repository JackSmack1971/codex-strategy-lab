# Behavioral handoff contract (not a native API)

Every delegated task specifies role, task ID, baseline OID, hypothesis/version, phase (draft review, frozen compliance, or result review when applicable), authorized read/write scope, prohibited data, budget, dependencies, required skill, exact input artifact digests and expected output. Worker returns JSON or equivalent structured record with task_id, role, baseline, phase, input_digests, status (COMPLETE/BLOCKED/INCONCLUSIVE), artifact_refs, findings, checks (command, exit status, artifact), limitations, and next_action. Findings identify artifact, severity, observation, consequence and proposed correction. Domain records use existing schemas, not this handoff envelope. Supervisor verifies actual artifacts and results. Only supervisor writes active ledger/evidence store and dispatches registered trials; child synthetic fixture stores must be isolated.

## Reviewer provenance

For objection reviewer_agent_id use the actual child thread/agent identity reported by native spawn/session metadata, correlated by supervisor with the delegated task and reply. Role name, generated UUID, or model assertion alone is not identity evidence. Retain source reference and parent/child correlation. For reviewer_context_digest use a runtime-provided digest of the actual reviewer context only when its scope and origin are documented and observable, or compute SHA-256 of a complete captured reviewer-visible input snapshot using research.identifiers.digest on a canonical JSON record containing the exact task, instructions, supplied artifacts/content digests, context messages and other reviewer-visible inputs, with snapshot scope and source recorded. Supervisor verifies the capture and digest. A handoff-only digest or hash of a role prompt is not a full context digest; if full input cannot be captured, do not label a partial digest as complete. Never retain secrets or hidden reasoning to satisfy this requirement; unavailable safe capture is a blocker.

If either provenance field is missing, return a proposal OUTSIDE the objection schema with task_id, claim, assumptions, test_specification, artifact_dependencies, severity, materiality, missing_provenance and status PENDING_PROPOSAL (or BLOCKED handoff). Do not manufacture placeholder fields or submit it as schema PENDING. Supervisor must not discard material proposals to obtain REVIEW_RECORDED; resolve provenance or stop the dependent path. For valid objections use research.contracts and adversarial.execute; do not assign UPHELD/REFUTED by opinion. Synthetic test identifiers are fixture-only and must never be reused as real identities. Record provenance references alongside review evidence without modifying its required schema.

Reviewer roles are behaviorally read-only with bounded scratch verification; inherited permissions remain authoritative. Methodology, adversarial and evidence roles disable apps, plugins, persistent memories and permission requests; none are needed for repository-local evidence review. Keep shell for actual deterministic verification and inspect effective exposure; plugin/MCP and network controls remain separate. Do not infer independent isolation or total context visibility from configuration. Store validated evidence via existing mechanisms; no competing research ledger.
